# 朱里様専用「今日のカード」ブラウザデモ

朱里様のフォロワーが、朝にスマホで恋愛のカードを1枚引き、その日の自分に向けた言葉を受け取る体験を確かめるためのデモです。
打ち合わせでは朱里様ご自身に回答していただきます。カードの解釈と音声を聴いたうえで、「この言葉なら自分のフォロワーに届けたい」と思えるかを確認します。

- 開く URL：`/akari-daily-card/`（**ゲーム一覧 `index.html` には載せていません**。`noindex` を指定済み）
- 受け入れ確認パネル：`/akari-daily-card/?debug=1`、またはヘッダーの「朱里」を素早く5回タップ
- 新規ユーザーとして開き直す：`/akari-daily-card/?reset=1`

> SPEC.md の本文は未確認です。データモデル、認証、イベントの必須属性、TTS の対応範囲は、着手時に照合してください（「本番への置き換え」参照）。

## 3. 体験の流れ（仕様案との対応）

### 3.1 ブランド・文体
- ヘッダーは「朱里｜今日のカード」。ホーム、オンボーディング、カード結果、音声、ペイウォールのすべてで同じ表記です。
- 配色は藤色（`#F7F3FB`〜`#6A4F8F`）と生成り（`#FBF7EF`）です。見出しとカード名は明朝体（Shippori Mincho）、本文は丸ゴシック（Zen Maru Gothic）にしています。
- 「体験版・文言は監修前」は、初回ホームとカード結果に表示します。音声には説明を挟まず、再生ボタンの近くに「デモ用の合成音声」と表示します。
- 16時〜翌4時（日本時間）は背景を少し夕暮れ寄りにし、カードを引く画面の文言も「今日をそっとふり返りながら」に変えます。

### 3.2 オンボーディング（6問＋音声設定2項目＝8項目）
| 画面 | 質問 | 入力・挙動 |
|---|---|---|
| 1 | なんとお呼びしたらいいですか？ | 必須、12字まで。「音声では『〇〇さん』とお呼びします」とその場で表示（さん・ちゃん・様などは重ねません） |
| 2 | 今の恋に、いちばん近いものは？ | 必須。片思い／交際中／復縁希望／婚活中／パートナーとの関係改善（補足文つき） |
| 3 | この恋で、いちばん願っていることは？ | 自由記述・スキップ可（120字） |
| 4 | 今は、どんな状況ですか？ | 同上 |
| 5 | 今、いちばん心に引っかかっていることは？ | 同上 |
| 6 | 願いが叶ったら、どんな一日を過ごしたいですか？ | 同上 |
| 音声 | いつ聴きたいですか？／どんな声のトーンが心地よいですか？ | 朝・夜・両方／優しい・力強い・落ち着いた。初期値は「朝」「優しい」。試聴ボタンあり |

- 3〜6の例文（placeholder）は、2で選んだ恋愛状況ごとに切り替わります（5状況×4問＝20例文）。
- 入力欄が空のとき、ボタンは「書かずに次へ」になります。
- 「お相手のお名前や連絡先は、書かなくて大丈夫です」と各画面に表示します。
- 途中の入力は端末に保存します。再読み込みしても続きから再開できます。

### 3.3 カード選定・生成
- **選定**：恋愛状況ごとの重み × シード（`{ユーザーID}:{日本時間の日付}:akari`）で1枚を決めます。死神・悪魔・塔は重みを下げ、前日と同じカードは選ばれにくくしています。7枚の扇から選ぶのは演出で、どれを選んでも結果は同じです。
- **解釈文**：200〜300字。構成は「気持ちへの共感（5の回答のカテゴリから） → カードの恋愛的な意味 → 願い（3・6のカテゴリ）に結びつけた前置き → 今日の小さな行動 → 締めの一文」です。
  - 自由記述の本文はそのまま使いません。「連絡・返事を待つ気持ち」「過去の別れ」などのカテゴリだけを読み取ります（10カテゴリ＋状況別の既定文）。
  - 願いの入力がない場合は、恋愛状況をもとに前置きを選びます。
- **アファメーション**：カードから2文、願いのカテゴリがあればもう1文（最大3文）。
- **自己チェック**：文字数、アファメーションの数、避けたい言い回し（`config.js` の `avoidPhrases`）を検査し、結果画面の「監修用メモ」に表示します。
- **同日の再訪**：保存済みのカード・解釈・台本を返します。メモリ内の処理中フラグとタブ間のロックで、再読み込み・連打・複数タブでも生成を重複させません。

### 3.4 ガイド音声
- 台本は、導入（呼び名を一度だけ）、呼吸、カードの紹介、解釈、今日の小さな行動、アファメーション、最後の一言の順です。
- 朝と夜で導入と行動のパートが変わります。夜は「今日、このカードのように過ごせた瞬間はありましたか」とふり返る構成です。声のトーン3種で言い回し・話速・高さが変わります。
- **長さ**：台本の段階で推定2分15秒に合わせます。再生中は実際の読み上げ時間を測り、残りの「間」（呼吸など）を伸縮して2分15秒に寄せます。間は最短でも0.8秒残します。
- 先にカードと文章を表示し、その場で「音声を準備中…」と伝えます。音声だけ失敗した場合は「音声だけ、もう一度準備する」で同じ台本から再試行でき、「字幕だけで体験する」も選べます。受け入れ確認パネルの「TTS失敗テスト」で失敗を再現できます。
- 再生はボタン操作で始まり、一時停止・再開ができます（再開は止まった一文の頭から）。画面を閉じたりアプリを切り替えたりすると、自動で一時停止に揃えます。
- シーク（末尾への移動）はありません。**自然に最後まで再生したときだけ** `audio_completed` を送ります。
- 字幕表示はオンオフでき、朝の音声と夜の音声も切り替えられます（打ち合わせで両方を聴いていただくため）。
- 始まりと終わりに小さな鈴の音が鳴ります（Web Audio）。
- 端末に日本語の声が複数あるときは、右上のメニューで声の種類を選んで試聴できます（Android は声の差が大きいため）。
- 「朱里からのひと言」が記録されていれば、最後の一言の直前に「朱里さんからの、ひと言です。」として読み上げます。

### 3.5 再訪ホーム・ペイウォール
- 初めて結果を開いた日を「1日目」とします。同日の再訪では増やさず、翌日に結果を開くと「2日目」になります。
- 明日のカードは裏向きで「明日のカードは、明日の朝に。」と予告し、カード名は伏せます。
- 翌日に開くと、質問なしでそのままカードを引けます（同じ生成処理を、その日の初回アクセスで呼び出します）。
- ペイウォールは再訪ホームの「明日からも続ける」から開きます。音声を最後まで聴いたかどうかとは独立しています。
  - 見出し「毎朝、今日のカードを」、内容「恋愛の状況に合わせた、毎日のカードとガイド音声」、料金「7日間無料、その後は月額1,200円（想定）」、ボタン「7日間無料で試す」
  - タップすると「体験版です。申し込みや請求は発生しません」と表示し、`paywall_plan_tapped` を記録します。連打しても1回だけです。

## 4. 計測

URL を開いた人ごとに `demo_<UUID>` を発行し、同じブラウザでは同じ ID を使い続けます。

| イベント | 記録条件 | 主な属性（本文は含めない） |
|---|---|---|
| `onboarding_completed` | 8項目の確定内容を保存できたとき（任意項目のスキップを含む）。1ユーザー1回 | `relationship`, `name_provided`, `wish_provided`, `situation_provided`, `worry_provided`, `ideal_day_provided`, `skipped_count`, `listen_time`, `voice_tone` |
| `audio_completed` | 再生が自然に終わったとき。1ユーザー1日1回 | `card_id`, `audio_mode`, `voice_tone`, `playback`（tts/captions）, `elapsed_seconds`, `estimated_seconds` |
| `paywall_plan_tapped` | 無料体験ボタンを押したとき。1ユーザー1回 | `plan`, `source`, `day_count`, `audio_completed_today` |

全イベント共通の属性：`variant`, `app_version`, `date_jst`, `ua_mobile`, `ua_platform`

- 記録形式は `{ id, user_id, event_name, created_at, properties }` です。
- `config.js` の `analytics.supabase` に `url` と `anonKey` を入れると、Supabase の `events` テーブルへ REST で送ります。送信に失敗した分は端末に残し、次回に再送します（`id` で重複を無視）。未設定のときは端末内だけに記録します。
- **属性名は仮です。SPEC.md に合わせて差し替えてください。** 呼び名・願い・状況・悩みの本文は、イベントには一切含めません。

## 5. 公開前の受け入れ確認

iPhone Safari と Android Chrome それぞれで行います。

1. `?reset=1` を付けて共有 URL を新規ユーザーとして開く
2. 回答 → カード → 結果 → 音声を最後まで聴く → ホーム → 「明日からも続ける」 → 「7日間無料で試す」
3. `?debug=1` で確認する
   - [ ] 3イベントが同じ `user_id` で記録されている
   - [ ] 「7日間無料で試す」を連打しても `paywall_plan_tapped` は1件だけ
4. 別ブラウザ（または `?reset=1`）で、音声を途中で止めて戻る
   - [ ] `audio_completed` が付いていない
5. 再読み込みして開き直す
   - [ ] 同じカード・同じ解釈が表示され、日数は「1日目」のまま
6. パネルで「＋1日」を押す
   - [ ] 質問なしで新しいカードを引け、ホームが「2日目」になる
7. パネルで「TTS失敗テスト：ON」にして新しい日のカードを開く
   - [ ] カードと文章は表示され、音声だけ失敗表示になる
   - [ ] パネルで「TTS失敗テスト：OFF」に戻し、「音声だけ、もう一度準備する」を押すと、同じ台本のまま音声が準備できる

自動テスト（Playwright、iPhone 13 と Pixel 7 のエミュレーション、日本語音声のスタブ）で上記の 1〜7 は確認済みです。実機の Safari・Chrome の音声（声の種類、マナーモード時の挙動）は、公開前に必ず実機で確認してください。

## 7. 本番への置き換え

| デモ | 本番 |
|---|---|
| `generator.js` の `generateDaily()`（テンプレート組み立て） | サーバーでカードを選定し、Claude API に「選定済みカード＋回答」を渡す。解釈文・アファメーション・音声台本を構造化出力で受け取る（スキーマ例は `config.js` の `claude.outputSchema`）。メソッドプロンプトは `method.interpretationAxes` / `rules` / `avoidPhrases` から組み立てる |
| 端末の合成音声（Web Speech API） | 台本ができたあとに TTS を実行し、音声ファイルを保存して `<audio>` で再生。トーンは TTS の声・話速と台本の言い回しで調整する。生成後に実際の長さを確認し、2〜3分の範囲外なら間を調整して再合成する |
| `localStorage` に保存 | Supabase：ユーザー、回答、日別のカード・解釈・音声 URL、events |
| `demo_<UUID>` | SPEC.md の認証方式（匿名認証など）に合わせる |
| 日付のずらし（デバッグ） | 削除する |

同日の再訪、重複生成の防止、音声だけの再試行、イベントの重複防止は、本番でもサーバー側で同じ規則（ユーザーID＋日本時間の日付で一意）にします。

## 8. 注意事項
- カードは大アルカナの名称・象徴・一般的な意味だけを使っています。カード面は `cards.js` で描いたオリジナルの線画（星・月・草花）で、既存デッキの絵柄は使っていません。現在は正位置だけで読んでいます。逆位置を使うかどうかは監修事項です。
- 占いの結果として、相手の気持ちを言い当てたり、復縁・成就を保証したりする表現は使わない方針です（`config.js` の `method.rules`）。
- 入力内容はその端末の `localStorage` にだけ保存されます。設定メニューの「入力内容をすべて消す」で削除できます。
